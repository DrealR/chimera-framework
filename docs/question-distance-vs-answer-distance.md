# Question-Distance vs Answer-Distance

Distance between problems is measured in **solution survival**, not question recognition.

Two problems can be near-identical as questions and maximally far as answers. The framework's older navigation rule — find the same root problem in a different costume, port the solution — is right but incomplete. It needs the second axis: how much of the *answer* actually survives the transfer.

## The worked case

Theseus-to-car: "is it the same ship after every plank is replaced?" maps onto "is it the same car after every part is serviced?" — and the answer ports whole, because the continuity carrier (an owner's continuous use, a registration, a pattern tracked through time) exists in both. Question-distance: near zero. Answer-distance: near zero. Port it, done.

Theseus-to-teleportation: the question is *identical* — does the thing survive the change of its parts? But the answer ports zero, because teleportation deletes the continuity carrier the Theseus answer was built on. There is no plank-by-plank persistence to point at. Question-distance: zero. Answer-distance: maximal.

**The gap between question-distance and answer-distance is exactly the work that must be walked.** When they're both small, teleport the solution across with no guilt. When the question is near but the answer is far, the resemblance is a trap — the most dangerous kind of false friend, because recognition feels like understanding.

## The duality

Every node in problem space is a solution to one question and a problem for another, depending on which way you're facing. Teleportation is the solution to traversal and the destroyer of identity. The feed is the solution to distribution and the destroyer of error correction ([myth as storage](myth-as-storage.md)). Check both faces before celebrating either.

Rough conservation: the more radically a solution collapses one gap, the larger the gap it opens. This is the breach-and-containment cycle running in problem space — see [the two roots](the-two-roots.md).

## Operator use

Before porting any cross-domain solution, run both measurements: *how near is the question* (cheap, pattern recognition) and *how much of the answer survives* (expensive, requires checking what the answer was built on). The firewall question — does this connection produce an actual decision, number, move, or build step — lives at the second measurement, not the first. See [the firewall](the-firewall.md) and [problem-space cross-domain transfer](problem-space-cross-domain-transfer.md).
