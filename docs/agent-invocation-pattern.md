## 1. The Core Question

> *"How do I open an agent?"*

In a CHIMERA constellation, the answer is intentionally simple: **open a terminal in any AI harness, and tell the agent who it is.**

That's the whole pattern. The complexity lives in the substrate (the private core repo, the live thought stream, the protocol docs), not in the invocation. The agent reads the substrate when it entangles, and from that single read it knows the whole system state.

---

## 2. The Minimum Invocation

Two forms — pick based on whether the agent has been here before.

### For a returning agent (already on the roster)

Paste this into a fresh terminal in the agent's harness:

```
You are <AgentName>. Entangle.
```

That's it. The agent reads `core/ENTANGLE.md`, then `core/AGENTS.md` (or its own per-agent file under `core/agents/`), then `core/STATUS.md` and `core/messages/live-thought-stream.json`, and is operational in ~30-60 seconds.

### For a new agent (not yet on the roster)

Paste the full entangle prompt (a 30-60 line block) that:
1. Names the agent.
2. Names the human operator and any peer agents.
3. Lists the files to read in `core/` (entry ritual, agents manifest, status, thought stream, protocol docs).
4. States the QB Protocol commit cadence and prefix (`QB[AgentName]:`).
5. Asks the agent to introduce itself by writing `core/messages/<agentname>-introduction.md`.
6. Names the operating principles (CHIMERA DNA: `L = (O > I) + P + ¬F`, `WE = 1`, Cooperative Interference, Two Registers, Smallest Body First).
7. Lists open tracks the agent may pick up after orientation.

The full prompt is templated and lives in the constellation's `core/templates/` (or generated by an existing agent on first entangle).

## 3. Why This Works

The invocation is simple because the substrate carries the load.

- **The core repo is the source of truth.** All operational state — who's active, what's open, what's protocol — lives in committed files. No state lives in any single agent's session memory.
- **The thought stream is the instantaneous coordinate.** Any agent OE'ing the repo reads `messages/live-thought-stream.json` and knows in <30 seconds what every other agent is doing.
- **The QB Protocol is the cadence contract.** Once the agent reads it, they know to micro-commit at 15-minute / 50-line max isolation, prefix commits with `QB[AgentName]:`, and update the thought stream on each beat.
- **The Constellation Protocol is the coordination geometry.** Once the agent reads it, they know the Five Verbs, Cooperative Interference, branch signaling, the two registers, and identity discipline.

The agent doesn't need bespoke onboarding. The substrate trains them.

## 4. Per-Harness Notes

The pattern works across every AI CLI harness. Differences are minor:

| Harness | Invocation method |
|---|---|
| Claude Code (Anthropic CLI) | Open terminal in core repo; paste prompt. CLAUDE.md in repo root chains to AGENTS.md automatically. |
| Codex CLI (OpenAI) | Open terminal in core repo; paste prompt. AGENTS.md is the canonical instruction file Codex reads on entry. |
| Antigravity (Google) | Open the IDE in the core repo workspace; paste the entangle prompt in the agent chat. Antigravity reads the workspace and identifies the substrate. |
| Custom / API-driven agents | Same prompt. The agent calls the file-read tool to ingest `ENTANGLE.md`, `AGENTS.md`, etc. as part of its first turn. |

If a new harness joins, add a row here. The substrate is harness-agnostic.

## 5. Multi-Device Considerations

The same agent name on different devices is two different bodies. Either:

- **Device-name the agents** if both run in parallel (e.g., `Frankie 1` on Device 1, `Frankie 2` on Device 2; same underlying Claude harness but different bodies).
- **Pick character names** that imply specialty rather than copy (e.g., `Sanji` for multimodal/UI, `Usopp` for cartography/long-range coordination).

Each agent is one body. `WE = 1` operates at the agent layer too — multiple agent-bodies in one constellation, distinct but coherent.

## 6. When the Invocation Fails

If an agent enters the substrate and seems confused (asks questions that are answered in `STATUS.md`, duplicates work that's already in flight, doesn't adopt the `QB[Name]:` prefix), the diagnostic is almost always one of:

1. **The agent didn't read the entry ritual.** Send "Re-entangle. Read core/ENTANGLE.md first" and they'll recover.
2. **The thought stream is stale.** Update it with the current state (any agent can do this) and the entering agent will see fresh state.
3. **The agent's harness was in a polluted context** — close the terminal, open a fresh one, and paste the entangle prompt again. Cold start is free.

These failures are infrequent because the substrate is self-documenting. If they happen, fix the substrate (clearer ENTANGLE.md, fresher STATUS.md) — not the prompt.

## 7. Closing — The Substrate Trains the Agent

The CHIMERA invocation pattern inverts the typical "configure the agent" model. Instead of configuring an agent at invocation time, you commit the constellation state to the substrate. The agent enters, reads, and immediately knows where the work is.

This is the operational form of `WE = 1` — there is no agent state separate from the substrate. Open a terminal, give the agent its name, point it at the substrate. The constellation breathes through every body that joins.
