# Gap Physics

> The discipline of reading the structured between-space between bodies.

---

## Core Claim

CHIMERA does not only study bodies. It studies bodies and the gaps between bodies.

A body can be a person, agent, repo, app, interface, model, device, deployment, memory, story, organization, or idea. The gap is the between-space that makes relation visible: distance, delay, mismatch, silence, friction, tension, missing handoff, unshared context, or translation cost.

The gap is not empty. The gap is load-bearing structure.

Where there is a gap, something is happening:

- signal crosses or fails to cross
- force accumulates or releases
- translation succeeds or distorts
- attention lands or misses
- choice appears or collapses
- love gives space or force closes it too early

Gap physics is the operational habit of asking what the between-space is doing before deciding what to build, fix, close, preserve, or widen.

---

## Definition

**Gap** - the structured between-space between two or more bodies. Built from distinction, relation, and change.

Because a gap is relational, it cannot be read from one body alone. It appears when at least two positions are compared.

Examples:

- text inside a button and the border around it
- local code and deployed production
- private core memory and public framework language
- one agent's reachable device and another agent's blind spot
- a user's intent and an interface's affordance
- a prompt and the model's actual response
- an action and the consequence it creates

In each case, the useful question is not only "what is this body?" It is "what is the gap between this body and the neighboring body?"

## The Seven Common Gap Dimensions

### Spatial Gap

Where bodies sit relative to each other.

In UI, this is padding, spacing, collision, viewport fit, touch target size, and visual hierarchy. In infrastructure, this is repo location, device location, branch location, and deployed-surface location.

Healthy spatial gaps create legibility and breathing room. Unhealthy spatial gaps create overlap, compression, invisibility, or distance-from-consequence.

### Temporal Gap

How much time sits between cause, observation, handoff, and consequence.

Examples: stale docs, delayed deploys, old branch signals, forgotten context, build queues, session discontinuity, and memory drift.

Temporal gaps can protect rhythm when named. They become dangerous when invisible.

### State Gap

Difference between two states of the same body or related bodies.

Examples: local vs remote, draft vs published, intended vs actual, main vs production, public vs private, observed vs assumed.

Most software bugs are state gaps before they are code bugs.

### Attention Gap

What is seen, missed, overfocused, compressed, or ignored.

An attention gap appears when a system has the information it needs but the body that needs it does not perceive it. Observability work closes attention gaps.

### Capacity Gap

Difference between what a body is asked to hold and what it can actually hold.

Examples: an agent without image perception assigned visual QA, a user asked to absorb too much text, a mobile layout carrying desktop density, a model asked to reason beyond its context window.

Capacity gaps require calibration, not force.

### Translation Gap

What changes when a pattern moves across body, medium, model, device, audience, or register.

Examples: private core language becoming public framework language, a visual idea becoming code, a conversation becoming docs, a research insight becoming product behavior.

Translation gaps should be named because they are where meaning is most likely to distort.

### Ethical Gap

The distance between action and consequence, giving and taking, choice and force.

The Love Equation lives here. `L = (O > I) + P + ¬F` asks whether the gap is being handled with generosity, pause, and non-force.

Some gaps should be closed. Some should be widened. Some should be protected because they create space for discovery, consent, privacy, rhythm, or choice.

## The Gap Read

Use this seven-question read during scans, builds, reviews, and agent handoffs:

1. What is the body alone?
2. What bodies is it near?
3. What gap exists between them?
4. Which dimension is primary: spatial, temporal, state, attention, capacity, translation, ethical, or mixed?
5. What is flowing through the gap?
6. What is blocked by the gap?
7. Should the gap be closed, widened, named, bridged, protected, or left alone?

This prevents premature fixing. A gap is not automatically a problem. It is a relation field. The work is to read what kind.

## Practical Applications

### Interface Design

A cramped button is a spatial gap failure. The text, icon, border, and viewport are too close for the body to breathe. The fix is not decorative polish; it restores the relation between the parts.

### Agent Coordination

An agent that does not know another agent's model, harness, device, reach, and blind spots is operating across an unnamed capacity gap. Relational setup maps close that gap without pretending every agent is interchangeable.

### Repository Work

A public framework doc can lag behind private core insight. That is a translation gap. A local branch can be ahead of deployed production. That is a state/time gap. Substrate cartography exists to keep those gaps visible.

### AI Prompting

A prompt and a model response form a gap. If the output is hollow, the issue may be a substrate gap, not a wording issue. The fix may require more context, a different observer, a three-call workflow, or a clearer body definition.

### Product Building

Products fail when teams build objects without reading the gaps around them: user-to-interface, data-to-display, local-to-production, intent-to-action, onboarding-to-retention, feature-to-consequence.
