## The claim

**Search on X is a direct probe into the attention field.** It shows where attention is concentrating around a term *without* waiting for the opaque For You algorithm to curate for you.

> Latest search ≈ a **live slice** of the high-velocity layer around a keyword.  
> Top search ≈ **accumulated** high-concentration history around that keyword.

Use both. Prefer **Latest** for present-moment positioning and planting.

---

## Sensor comparison

| Tool | What it shows | Strength | Limitation |
|------|---------------|----------|------------|
| **For You** | Algorithm’s guess of what you’ll engage | Personalized, surprise | Opaque; loop risk |
| **Following** | Only chosen accounts | Controlled, lower noise | Narrow; can go stale |
| **Search · Latest** | Real-time flow around a term | Most transparent *now* slice | Noisy without good keywords; still needs recency eyes |
| **Search · Top** | What has stacked attention over time | Historical concentration map | Weak for live plant timing |
| **Field app** | Ranked deck inside a recency window | Hierarchy + CHIMERA posture | Needs ingest / pull; not a full platform replacement |

Search does **not** replace Tier 1 recency in Field — it is a **discovery sensor** that *feeds* the same hierarchy.

## LLM parallel (structure, not identity)

| LLM | X search practice |
|-----|-------------------|
| Prompt | Search term + mode (Latest/Top) + time filters |
| Attention mechanism | Ranking / surfacing of posts |

Both use **attention mechanisms** to surface what the system weights as relevant *now*. You are not the model — you are the **operator** choosing the probe and what to plant into the result. ## How it fits positioned planting

```text
1. Choose region     — Magnet topics / live event / question you care about
2. Probe             — Search Latest on tight keywords
3. Recency gate      — Only engage posts still in live window (15–45 min)
4. Momentum read     — Early rates, R vs C soil, branch vitality if visible
5. Curvature check   — Do I have a real bend (Holy Man / clean redirect)?
6. Plant once        — then non-interfere
```

### During high-density moments

Streams, sports, flashpoints: don’t only scroll For You. **Probe** event keywords in Latest to find trunks that are *actually* concentrating eyes right now. Then apply the same Tier 2 momentum + CHIMERA plant rules. See [Live Event Concentration](live-event-concentration.md).

### Keyword craft (light)

- Specific enough to cut noise (`ishowspeed argentina` > `soccer`)  
- Loose enough to catch real talk  
- Rotate 2–4 probes; don’t live inside one term (loop trap)  
- Magnet `current_direction` → preferred probe set

## Field tool integration

| Phase | Role of search |
|-------|----------------|
| **Now (operator)** | Manual Latest probe → paste/ingest into Field or plant from X |
| **1** | Ingest from Grok/Frankie pulls that used search Latest + recency |
| **2** | Optional keyword interest list (Magnet topics) as soft boost — already partially via magnet topics + live event notes |
| **Later** | Side-by-side Latest vs Top literacy (how a topic’s attention aged) |

**Law:** Search is a **complementary sensor**. It never demotes the recency hard gate. No auto-plant from search results.

## Strategic method (copy)

```text
During live density or daily pass:
1. List 1–3 probes (event + magnet topics)
2. X Search → Latest → skim last ~30 min only
3. Pick 1–3 trunks with real momentum / soft medium
4. Field or direct: CHIMERA pre-plant → Holy Man / clean bend
5. Plant once → step back
6. Optional: note felt bend / flat for literacy
```

## Firewalls

- Search can become another addiction loop — time-box probes  
- High Latest volume ≠ fertile soil (bots, pile-on, spam) — still read signatures  
- Don’t confuse Top (history) with live plantability  
- Optimization of “best keyword” without genuine care fails O>I
