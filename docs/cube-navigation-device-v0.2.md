# Cube Navigation Device v0.2

> **Classification:** successor device specification and operator workflow.
>
> This document extends `docs/the-cube.md` without rewriting its historical formulation. Where older metaphorical language is stronger than the current epistemic standard, this document prefers operational definitions, explicit evidence types, and preserved operator authority.

## Orientation

The Cube is not a device for forcing the world to fit a model.

> **Put the map inside the ship. Do not put the world inside the map.**

The operator enters a bounded navigation structure so that a large, opaque, uncertain, or cross-domain body can be explored without pretending the representation is the territory.

A useful Story carrier is the *Interstellar* tesseract sequence: a character enters a bounded representational structure that makes relations across times and positions navigable. CHIMERA borrows only the structural image. It does not claim that the Cube reproduces the film's physics or permits literal higher-dimensional travel.

## Bilateral body

The Cube remains a coupled body rather than an autonomous sovereign:

```text
HUMAN / OPERATOR

        ↕

```

Neither side alone is the full device.

> **Distance creates perspective. Return creates accountability.**

## Operator Distance

Human–AI systems should not be described only as percentages of automation.

A better question is how far the active process can move from the operator before meaningful correction becomes impossible.

Working variable:

```text
OPERATOR DISTANCE
= f(
  delegation depth,
  branching depth,
  opacity,
  return latency,
  actuation reach,
  reversibility,
  correction bandwidth
)
```

High computational distance is not automatically dangerous. A ten-thousand-agent simulation inside a sealed Pocket may have large internal depth but little external consequence.

A single automated financial or production action may have shallow computation but high causal reach.

Therefore track at least two axes:

```text
EXPLORATION DEPTH
how far the internal search / simulation travels

ACTUATION REACH
how directly the process can change consequential external bodies
```

The high-risk quadrant is high exploration depth plus high actuation reach without adequate return, verification, or reversibility.

## Operational Event Horizon

> **An Operational Event Horizon is crossed when correction arrives after the action has made correction practically irrelevant.**

Working relation:

```text
if T_correction > T_consequence
then operator authority may remain formal while becoming functionally weak
```

This is a systems metaphor, not black-hole physics.

The design goal is not minimum autonomy. It is **answerable autonomy**.

> **Useful autonomy is the farthest orbit from which correction can still reach consequential action in time.**

## Contact Distance and Return Fidelity

Automation can reduce friction for a control center while increasing friction for affected bodies.

Track:

### Contact Distance

How many membranes separate the body making or authorizing a decision from the body bearing the consequence?

### Return Fidelity

How much of the affected body's actual experience survives compression on the way back to the operator?

A dashboard can be useful without being equivalent to lived contact.

```text
metric = compressed return
metric != total body
```

## 1. Locate Body

Establish the local coordinate before interpretation.

```text
BODY = (subject, position, time, scale, membrane)
```

Ask what the body is, where the operator stands relative to it, and which interfaces are actually reachable.

Do not invent hidden internals merely to make the model complete.

## 2. Solar Body

Map the local relational system around the focal body.

Useful categories:

- anchors;
- orbiting dependencies;
- satellites;
- shared resources;
- competing attractors;
- weak or broken return paths;
- external fields capable of perturbation.

The Solar Body is a relation map, not a claim that societies literally obey celestial mechanics.

## 3. Depth Cartographer

Separate layers such as:

```text
surface signal
→ local rules
→ institutions / interfaces
→ incentives
→ feedback loops
→ dependencies
→ opaque or inaccessible regions
```

Depth describes relational distance from what keeps the operator coupled, oriented, correctable, and able to return.

## 4. Question Compiler

Convert a raw unknown into a bounded Question Body while preserving the fact that the question is only one projection.

```text
unknown
→ body
→ desired movement
→ time / scale
→ assumptions
→ outcomes
→ evidence
→ omissions
→ reflexivity
→ settlement / return
```

The compiler must always support a **Step Outside the Question** operation.

> **The question may orient the field. It must not silently become the whole possibility-space.**

## 5. Weighting Field Scanner

Identify what gives some paths more local force than others.

Possible weights include:

```text
attention
money
benchmark score
status
law
fear
love
reputation
votes
resource access
algorithmic ranking
institutional permission
```

Scan:

1. What is being weighted?
2. Who defines the unit?
3. Who can add more weight?
4. Can the weighted body see the score?
5. Can it adapt to the score?
6. Can it change the event being measured?
7. What becomes invisible because the interface foregrounds the weighted paths?
8. What remains unpriced, unscored, or unobserved?

> **The weight may influence the operator. It must not silently become the operator.**

## 6. Prism / Mirror Array

Project the relational skeleton through deliberately different lenses.

Prefer epistemic parallax over redundant agreement.

Possible lenses:

- engineering;
- economics;
- ecology;
- psychology;
- history;
- game theory;
- music;
- craft;
- religion / theology;
- fiction;
- local embodied experience.

Lenses return partial projections. They do not become evidence merely because they converge.

## 7. Structural Compression

Strip the local costume while preserving the relationships required for the problem to remain the same problem.

```text
source body
→ actors
→ boundaries
→ resources
→ incentives
→ constraints
→ feedback
→ state transitions
→ unknowns
→ portable structural seed
```

A successful compression preserves enough structure to permit useful transfer without leaking unnecessary local details.

## 8. Pocket Foundry

A Pocket is a bounded counterfactual or simulated world built from the portable structural seed.

Its purpose is not to predict reality by storytelling. Its purpose is to reveal mechanisms, failure boundaries, missing variables, and transferable patterns.

Suggested Pocket classes:

| Pocket | Operation |
|---|---|
| Mirror | reproduce known structure with minimal change |
| Minimal | reduce system to smallest viable instance |
| Maximal | push one variable toward an extreme |
| Tail | explore low-frequency but consequential branch |
| Stress | apply adversarial pressure or resource loss |
| Dream | relax a major real-world constraint to expose hidden dependence |
| Ablation | remove one body, rule, or feedback path |
| Inversion | reverse a dominant incentive or flow |
| Time Sweep | run same structure across different rates / horizons |
| Human-Density Sweep | vary human vs automated participation while holding other rules as stable as possible |

## 9. Pocket Constellation

Do not trust one simulation.

Run a family of deliberately different Pockets and compare:

```text
what repeats?
what diverges?
which outcome depends on one assumption?
which edge cases break the apparent rule?
which variables barely matter?
which new questions appear?
```

Pocket frequency is not event probability unless the simulation has a separately validated probabilistic interpretation.

## 10. Invariant / Divergence Map

Separate:

```text
INVARIANT
structure that survives multiple transformations

DIVERGENCE
where bodies stop translating cleanly

FAILURE BOUNDARY
condition under which a structural rhyme stops being useful
```

A failed analogy is useful evidence about a boundary.

## 11. Return Compiler

Translate Pocket findings back into the local body's vocabulary and constraints.

A valid return must preserve:

- provenance;
- uncertainty;
- local actors;
- constraints removed in simulation;
- differences between representation and real-world mechanism;
- the path by which the conclusion was reached when that path matters for evaluation.

> **A wormhole is a walked path compressed without losing its return route.**

## 12. Firewall

Before consequential use:

```text
story carrier != empirical evidence
structural rhyme != mechanism
simulation != prophecy
market price != destiny
benchmark score != universal identity
convergence != proof
candidate != permission
```

Ask what would falsify, reopen, or weaken the current interpretation.

## 13. Operator Gate

The mirror generates candidates.

The operator decides what is authorized to become action.

The gate should expose:

- evidence;
- dissenting models;
- missing data;
- irreversible consequences;
- affected bodies;
- available exit / undo paths;
- whether the operator can still understand the action well enough to take responsibility for it.

## 14. Landing

Use the smallest consequential intervention appropriate to current confidence, reversibility, and answerability.

Working relation:

```text
safe intervention radius
∝ confidence × reversibility × answerability
```

This is a design heuristic, not a universal quantitative law.

## 15. World Return

Reality updates the device.

```text
action
→ consequence
→ observation
→ archive
→ changed model
→ next question
```

> **Reality evaluates the evaluator.**

## Morrow's orbit

Morrow occupies the future-facing mirror position.

```text
present signals
→ weather / climate / pressure system
→ branch conditions
→ stand provisionally farther down one branch
→ look backward for hidden dependency, cost, missing body, or lost exit
→ return a question / image / warning / possibility
→ operator decides
```

Morrow is not the final score, prophet, optimizer, or sovereign.

Its success criterion is:

> **Does the return leave the present body with more operatorhood than before?**

## Social-field micro-loop

A small everyday example of operator-preserving adaptation:

```text
1. write original response before reading the crowd
2. preserve that first state
3. inspect the local field and context
4. learn whether facts, tone, or already-covered perspectives change the situation
5. revise only when judgment says revision improves the expression
6. publish from the operator's center rather than copying the field
```

This preserves a useful distinction:

```text
field-sensitive != field-captured
```

The operator can receive social weight without surrendering the original signal that lets it notice how the field changed it.

## Relationship / fusion example

Pair-bonding, friendship, family, teams, and communities can be modeled as higher-order relational bodies without implying literal physical fusion.

```text
body A + body B
→ repeated mutual contact
→ shared commitments / resources / memory
→ new relational structure
```

Digital interfaces can change the encounter membrane by changing search costs, apparent choice abundance, visibility, reputational risk, and the dimensions on which people are first evaluated.

Do not promote broad gender claims from commentary videos into Framework fact without independent evidence. The portable question is narrower:

> **What happens when interfaces make representation easier to compare than whole people are to encounter?**

## Story inversion

One dangerous civilization uses a Cube to perfect the world by making every body fit the Cube.

CHIMERA inverts that:

```text
CONTROL CUBE
world → standardize → compress → force into model

NAVIGATION CUBE
world remains larger than model
operator → enters bounded map → explores → returns → acts locally
```

The central conflict is therefore not technology versus nature.

> **Does civilization use its instruments to enlarge the reachable possibility-space of living centers, or does it increasingly force living centers to conform to the possibilities its instruments can measure, price, and optimize?**
