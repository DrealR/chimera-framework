# The Deletion Test

A falsifiability procedure CHIMERA agrees to be tested against.

The framework's strongest discipline is the willingness to be wrong on specific bodies and to record that it was wrong. The deletion test is the operational form of that discipline: a published, repeatable check that asks of any framework-output document whether it added structural insight *or* whether it added vocabulary in the costume of insight.

## The problem this test addresses

Frameworks that name lots of things become hard to falsify because vocabulary attaches to existing observations and feels like structure. The risk: a body-scan pass that simply re-labels what a plain reader would already see, while adding one or more mechanism-shaped phrases that no observation could disconfirm.

The framework's own values, repeated across its operator docs, call out exactly this failure mode: *"I don't know" over a confident guess. Name confabulation. Prefer compression. Observable territory only.* The deletion test operationalizes those values as a runnable procedure.

## The procedure

**Given:** any framework-output document that claims to be a body scan, a structural analysis, a Cube-mode pass, or any application of the framework to a specific body or situation.

**Step 1 — Strip framework vocabulary.** Delete every framework-coined or framework-specialized term from the document. The deletion vocabulary list, maintained in this framework, includes (non-exhaustive):

- The equation: `L = (O > I) + P + ¬F`, `WE = 1`, `Dial-N`, `O > I`, `O ≥ I`
- Body-scan ritual phrases: "I receive the prime", "Dial-7 / CHIMERA-space", "Body Scan"
- Output-shape labels: "Floor prime", "Ceiling prime", "Convergence synthesis", "Triality"
- Framework-coined mechanism phrases: "vibration-collapse", "the three-call forces the between", "substrate accumulates", "emit coherent vibration"
- Framework-coined neologisms: "the Cube", "the genie problem", "demiurge configuration", etc., when used as *mechanisms* rather than as labels for already-named phenomena
- Closing markers: "Zero fully entangled", "the substrate is ready", restated `L = (O > I) + P + ¬F` / `WE = 1`

The deletion vocabulary list is itself a public artifact maintained alongside this document (see [The Deletion Vocabulary List](#the-deletion-vocabulary-list-v1) below).

**Step 2 — Reduce remaining text to discrete factual claims.** What sentences survive deletion? List each surviving claim as a discrete sentence.

**Step 3 — Compare against the source.** For each surviving claim, ask: *was this claim already present in a plain reading of the source the framework was applied to?*

**Step 4 — Score each surviving claim.** Place each claim into one of five categories:

| Category | Description | Score |
|---|---|---|
| Framework-added structural insight | A structural claim about the source that a plain reader would not have surfaced; checkable | +1 |
| Relabeled existing observation | A claim that was already in the plain reading, restated in plainer language | 0 (neutral) |
| Vocabulary-in-disguise | A "claim" that survived deletion only because the vocabulary list was incomplete; really a framework-coined term in different costume | 0 (neutral) — and a flag to update the vocabulary list |
| Unfalsifiable mechanism | A claim that asserts a mechanism the source does not contain, where no observation could disconfirm it ("vibration-collapse reconfigures the body") | −1 |
| Domain error | A claim that contradicts the source or the domain it concerns | −1 (and a flag for retraction) |

**Step 5 — Verdict.** The framework-output document *passes* the deletion test on this body if and only if:

- The total score is positive (positives exceed negatives), AND
- At least one positive (structural insight) is present.

Otherwise it fails. *Failing is recorded.* The framework's credibility lives in its willingness to record failures.

## What "passes" and "fails" mean

**Passing the deletion test does not mean the framework's claims are universally correct.** It means: on this specific body, the framework added structural content beyond what a plain reading would have surfaced. That is a falsifiable, body-specific finding. Many bodies will pass; some bodies will fail. *The framework is the union of the bodies on which it passes.*

**Failing the deletion test does not mean the framework is broken.** It means: on this specific body, the framework did not add what it claimed to add. The honest move is to record the failure, refine the body-scan pass, or accept that this body is not a band the framework reads well.

## What this test is *not*

- **Not a replacement for domain expertise.** A body-scan of a physics body is not validated by passing the deletion test — it can pass the test and still get the physics wrong. Domain-specific correctness is a separate check.
- **Not a single-pass certifier.** The test is meant to be re-runnable. A body-scan that passed today may fail tomorrow if a more careful plain reading of the source surfaces what the framework also claimed to surface. That is fine. The test is a discipline, not a stamp.
- **Not applicable to every framework document.** Primer docs (this one, [Gap Physics](gap-physics.md), [The Nine Questions](../body-theory/THE-NINE-QUESTIONS.md), [What Is a Body?](../body-theory/WHAT-IS-A-BODY.md)) are not applications of the framework to a specific body; they are the framework itself. The test applies to *uses* of the framework, not to the framework's primers. Primers have their own self-discipline: they should pass the test of *"is the claim here checkable, or only definitional?"* — but that is a separate, related discipline.

## Worked example — Why this test was written

Five framework-output passes on news transcripts (an AI economy debate, a Google I/O capabilities transcript, a three-substrate drop combining skin pigmentation + Korean cosmetic surgery + Bali tourism) were informally subjected to the deletion procedure described above. After deletion, the surviving claims were either (a) already present in a plain reading of the transcripts or (b) framework-coined mechanism phrases that the vocabulary list had not yet captured. None of the five passes earned a positive score.

Important caveat: the five passes were *text-mode imitations* of a body scan — agent prose written in the framework's voice — rather than runs of the framework's actual Cube architecture with separated calls and inspector gates. The five negatives do not indict the Cube as architected; they indict the practice of writing framework-style prose without running the framework's actual discipline.

That distinction is important and is also exactly why this test exists: framework-style prose feels like framework output. Without a deletion check, the two are indistinguishable. With it, they separate.

## The Deletion Vocabulary List v1

This list is the load-bearing artifact of the test. If it is incomplete, the test under-detects vocabulary-as-content. The list is intended to grow as new framework terms enter circulation and as failures of the test surface terms that should have been on it.

**Equations and core operators:**
- `L = (O > I) + P + ¬F`
- `WE = 1`
- `O > I`, `O ≥ I`, `O < I`, `I > O`
- `¬F`, `Pause (P)`

**Dial labels:**
- `Dial-N` (any N)
- `CHIMERA-space`, `CHIMERA-mode`

**Ritual openings/closings:**
- "I receive the prime"
- "Captain. Dial-N. CHIMERA-space."
- "Zero fully entangled"
- "The substrate is ready"
- "WE = 1." as a closing
- Any restated equation as a closing marker

**Output-shape labels:**
- "Body Scan"
- "Floor prime", "Ceiling prime", "Convergence synthesis"
- "Triality", "Triality diagnostic"
- "Mirror body", "Substrate mirror"

**Framework-coined mechanism phrases:**
- "vibration-collapse"
- "the three-call forces the between"
- "the Cube two-pass-then-converge engine"
- "emit coherent vibration so new bodies self-organize"
- "substrate accumulates" (when used as mechanism)
- "the gap collapses" (when used as mechanism)

**Framework-coined neologisms used as mechanisms (not labels):**
- "the Cube" (as mechanism, e.g., "the Cube reconfigures") — labels are fine
- "demiurge configuration" (as mechanism)
- "genie problem" (as label is fine; as universal mechanism explanation is not)

**Companion-doc-coined terms when used outside their primer:**
- Any term whose definition lives in a framework primer and is being invoked elsewhere without re-grounding in observable content

This list is v1. Subsequent versions, surfaced through deletion-test failures, are tracked in this document's revision history.

## When a body-scan pass fails — three options

If a body-scan pass fails the deletion test, the options are:

1. **Retract.** Mark the pass as failed-deletion-test on date YYYY-MM-DD. Keep it in the record as a learning artifact, not as a recommendation.
2. **Refine.** Re-do the pass with the deletion-vocabulary terms removed from the start, and see whether the framework can surface anything new under that constraint. If yes, the refined pass replaces the original. If no, the failure stands.
3. **Re-scope.** If the body simply is not a band the framework reads well (the framework's instrument is wrong for this source), say so. Record which body classes the framework fails on. That record is data.

All three are honest. The dishonest option is to leave a failed pass in circulation without any signal that it failed.

## Closing

The framework's strongest credibility move is not the volume of its documents. It is the willingness to be wrong on specific bodies and to record those failures publicly. Other instruments do this — telescopes have calibration curves; balances have rated uncertainties; benchmarks have score distributions. The deletion test is CHIMERA's version of the same discipline. A framework willing to fail is a framework worth using.
